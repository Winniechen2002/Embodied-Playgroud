# 全部 410 项环境的评测协议

<!-- paper-evaluation-scope:start -->
Embodied Playground 的完整目录含 410 项任务。论文采用发射器仅 loaded 的评测范围：完整目录为 410 组／1640 条件；EP-100、EP-Easy、EP-Hard、EP-20 分别为 100／50／50／20 项、400／200／200／80 条件。每任务每组四条件，五套件等权评分。详见[论文集合定义](ep_subsets/README.zh-CN.md)。运行时另支持 ground；通用工程清单保留 510 组／2040 条件，不能直接作为论文分母。

协议版本：`environment-four-trial-v2`。权限版本：`2026-10-09-environment-l0-l3`。本文定义后续回合评测规则，不包含模型成绩。暂缓构建发行包与公开发布。

<a id="section-2"></a>
## 任务身份与测试次数

每项任务在每个测试组中必须取得 **4 个独立条件的有效结果**，执行前固定清单。四个条件全部计入，不挑最好一次，不替换有效失败。按[共享异常计数规则](#non-agent-failures)，经证据确认的非 agent 异常不计成绩、不占有效尝试次数，并为原条件补跑；实际启动数可多于四次。唯一目录有 410 项任务；初态模式、种子、观测档位和权限等级不增加目录任务数。

测试组固定 `(task_id, protocol_version, base_seed, initial_mode, operation_profile, observation_profile, capability_level, permission_version, tool_grants, budgets, implementation_revision)`。若评测 agent，还须固定其代码／版本和指令。任一字段改变就另建组，禁止混算或跨组沿用私有状态。标准清单使用 base seed 0；其他 base seed 是另行命名的扩展组。允许的 base seed 范围为 0..2147483644。

发射器分别建立 loaded 与 ground 组，每组四次；其余 310 项各建立一个 default 组。因此一个 base seed、一个固定权限／观测组合共有 **510 组、2040 个计划回合**：发射器 800，其余 1240。论文评测明确采用 loaded-only 子集；此处 510 组是运行时全部模式的工程清单。四个权限等级分别测试共计划 8160 回合。这些数字是计划数量，不是已执行数量。

<a id="section-3"></a>
## 随机化与固定扰动

统一的是四回合统计和隔离规则，不把发射器参数照搬到其他机器人。[机器可读清单](evaluation/tasks.json)为每项任务列出四次精确 reset seed、配置参数和预算。这是维护者配置，不得把完整清单作为客户端提示输入。

| 系列 | 四次映射 | 保持不变的条件 |
| --- | --- | --- |
| 发射器，100 项 | 保留原 `four-trial-v1`：四次采用同一个 base reset seed；弹簧 22/24/26/28 N/m、规定的发射器／弹药偏移、场景名 SHA-256 确定的主题轮换、static/static/drift/pulse 背景 | 作者目标、建筑、顺序、保护对象和 yaw 配置；loaded 与 ground 分组 |
| 汉诺塔，120 项 | 原有 `train` 采样器，reset seed 为 `base_seed + 0/1/2/3`；棋盘 XY 有符号均匀偏移不超过 0.004 m，yaw 不超过 2 度，质量因子 0.90–1.10、摩擦因子 0.92–1.08、灯光强度 700–1100 | 同一圆环起点／目标、尺寸、机器人、障碍和合法移动规则 |
| 二阶魔方，20 项 | 原有 `train` 采样器，seed 为 `base_seed + 0/1/2/3`；XY 偏移不超过 0.003 m，yaw 不超过 2 度，相对质量因子 0.94–1.06、相对摩擦因子 0.95–1.05、灯光强度 750–1050 | 作者指定的质量／摩擦倍率、起终角块状态、要求的四分之一转次数和机器人 |
| 三阶魔方，60 项 | 相同 base seed 和固定公开案例；作者 sky-light 强度分别乘以 0.85/0.95/1.05/1.15 | 打乱序列、逻辑朝向、初始位姿、物性、辅助机构和目标 |
| 孔明锁，60 项 | 相同 base seed 和固定公开案例；作者 sky-light 强度分别乘以 0.85/0.95/1.05/1.15 | 零件身份、初始／目标位姿、子任务范围、支撑关系和物理参数 |
| 书架，20 项 | 原生 reset 采样器，seed 为 `base_seed + 0/1/2/3`；按变体采样物体位置、姿态、箱内排列和允许的错放分配 | 变体物体集合、目标位置、靠墙要求、几何、评分容差和时限 |

汉诺塔使用 `random.Random("hanoi40-v1:{task_id}:{split}:{seed}")`；二阶魔方将 `cube20-v1/{task_id}/{split}/{seed}` 的 SHA-256 前 8 字节作为大端整数来初始化 `random.Random`。导出内容含实际采样参数，不只有范围说明。书架使用原生张量采样器及碰撞／拒绝约束，须私有记录 settling 后的实际状态。不同 seed 不保证每个物体都改变位置。

三阶魔方与孔明锁采用的是**四个固定视觉扰动**，不能称为随机谜题或物理布局泛化测试。仅改变 seed 不会改变其固定案例布局。灯光系数在创建场景前生效，不是客户端工具，也不允许回合中修改。四个灯光系数和发射器扰动均为人为规定的条件，不是真实世界分布样本，不能据此声称广泛泛化。nominal、heldout 工程矩阵独立保留；本协议采用已有 `train` 范围，不应标成 heldout 评测。

## 回合预算与评分

| 系列 | 物理／控制 Hz | 最多控制步数 | 仿真时限 | 外部墙钟时限 |
| --- | --- | --- | --- | --- |
| 发射器 | 1000 / 50 | 7500 | 150 s | 600 s |
| 汉诺塔 | 120 / 30 | 18000 | 600 s | 3600 s |
| 二阶魔方 | 240 / 60 | 18000 | 300 s | 3600 s |
| 三阶魔方 | 120 / 30 | 109800 | 3660 s | 19800 s |
| 孔明锁 | 120 / 30 | 36000 | 1200 s | 3600 s |
| 书架 | 120 / 30 | 30 × 变体秒数 | 50–410 s，逐任务给出精确值 | 3600 s |

网关 CLI 为注册回合固定上述预算。墙钟时间包含启动与初始化；统一入口通过外部进程监督器实施硬截止。正常到期按有效失败计数；运行时原始标签另行保留，不直接决定是否免责。运行时轮询只是协作式检查，不能中断卡住的仿真调用。生成清单或启动网关不等于提供完整批量评测器，也不证明墙钟硬限制已经实施。token／图片预算不是环境验收门槛；未来进行 agent 比较时仍须额外固定并披露相同资源预算。

使用每项任务的可信评分器及完整任务合同。发射器要求必要目标、规定的破碎／倒塌／顺序／损伤路径和保护条件；含保护对象的场景从最后一个必要目标命中后等待至少 3 s。汉诺塔要求精确目标、合法移动、正确落座、物理有效且连续稳定 1 s。二阶魔方要求精确目标、精确提交次数、1 度内定位、无活动层、角速度低于 0.05 rad/s、场景指纹不变且稳定 1 s。三阶魔方要求原生魔方复原、合法辅助机构动作、释放／回位／支撑及新鲜的 0.5 s 稳定窗口。孔明锁要求案例目标与释放，组装稳定 2 s、拆解稳定 1 s，并完整覆盖物理子步审计。书架要求全部布局规则连续成立 0.5 s。各系列文档链接数值评分实现与几何约束。

首次锁存的物理违规会否决成功，即使后来布局恢复正确。稳定时间必须在预算耗尽前满足，仅在最后一刻到达目标不够。正常墙钟超时、仿真时间或步数耗尽、物体丢失、物理违规、agent 自身异常或主动结束造成的未成功结果，均为有效失败。初始化／环境／评分器／模型服务等异常须按原因审计；只有经证据确认不是 agent 操作导致的失败或中断才剔除、不占机会并补跑。可恢复的动作拒绝不自动结束回合。未启动、待补或归因未明的条件属于调度／审计状态，不虚构成功或失败。记录 `attempt_accounting_version: non-agent-exclusion-v1`，保留原始终止标志、首次失败和异常证据；不能仅凭原始 `invalid` 标签自动剔除，也不能根据图像或动作请求已接受来推断成功。

<a id="section-5"></a>
## 隔离、权限与统计

每回合创建全新环境与客户端／agent 会话，只有维护者初始化和 reset。回合内保留所有破坏、消耗弹药、状态和记忆，不暴露 reset 或 reseed；回合间清空 agent 记忆、工作目录与缓存，并约束、记录外部持久服务。四次执行前固定代码和参数，不能利用前次私有结果调参。恢复可补尚未执行的条件及经审计剔除的非 agent 异常条件；已完成的有效失败不能因此重试。每次补跑建立新的实验记录并关联原记录，保持同一条件和单次预算；环境修复记录版本，改变组身份字段仍须另建组，不覆盖历史记录。

L0 允许标准 Python、NumPy、Pillow 和自写算法，禁止预置领域工具和外部视觉／抓取模型。L1／L2 工具同时要求明确授权和实际安装；L3 仅增加声明的特权只读访问。观测档位和动作单位按系列保留。读取不推进物理时间；相同请求 ID 重放原操作；终止后不可继续步进。网关不能证明任意外部 Python 客户端的全部依赖使用合规。

私有逐回合记录包括任务／组身份、回合编号、请求参数、实际初态和运行配置、源码／资产哈希、运行时版本、预算、权限档位、终止原因、首次违规、仿真／墙钟耗时及实际步数。详细评分诊断和隐藏状态保留在评测端；客户端只获得声明的公共观测、任务条件（包括发射器弹簧刚度）和过滤后的终局结果。可推断的回合映射不构成安全盲测。

完整组必须有四个条件的有效终局，指标为 `successful episodes / 4`；只有四次都成功，`all_four_success` 才为 true。条件尚未取得有效结果时，组为 `partial`，最终 `success_rate = null`、`all_four_success = null`；这是完成状态，不是第三种实验结果。保留 `observed_successes`、待补条件编号及明确标记的下界 `observed_successes / 4`。非 agent 剔除记录单列，不进入失败数或已评分尝试分母；补齐原条件后，历史剔除记录不再使组维持 partial。不缩小四条件分母、不只报最好一次。单独声明的多次有效机会实验另报其条件聚合口径，不冒充标准单次四回合成绩。环境 QA 报告独立记录，不含模型成功率字段。

<a id="section-6"></a>
## 生成与运行

在仓库根目录，使用具备相应依赖的 MuJoCo 或 Isaac 解释器执行：

```bash
python scripts/export_evaluation_protocol.py --check
python scripts/export_evaluation_protocol.py --base-seed 7 --output /tmp/evaluation-seed7
python scripts/environment_runtime.py --task-id hanoi_panda/panda/H01 --capability-level 0 --seed 0 --evaluation-protocol environment-four-trial-v2 --trial-index 1 --headless --output /tmp/hanoi-trial1
python scripts/environment_client.py /tmp/hanoi-trial1/session.json
```

示例客户端只做有限安全交互并结束，不负责解题。回合编号 1、2、3、4 分别使用独立进程和新输出目录。发射器分别选择 `--initial-mode loaded` 与 `--initial-mode ground`。注册回合拒绝自定义 split、弹簧、控制步数或墙钟预算覆盖。不传 `--evaluation-protocol` 时保留工程单实例接口，但不能将其标为注册的四次评测结果。

仓库中的清单由任务作者配置及版本化采样器生成，`--check` 检测生成内容和源码哈希是否过期。生成配置、文档检查或冒烟检查都不是完整四回合任务评测证据。新增条件清单的全量物理验收仍须独立完成。


<a id="section-7"></a>
## 新增系列的精确协议

双 Floating Sharpa 孔明锁与双 Panda 使用相同 30 个案例、四档灯光及 1200 s / 36000 控制步 / 3600 s 墙钟预算；其动作保留 56 维，并使用实测手指释放与手掌撤离条件。

ManiSkill 每项四次采用相同 base seed，固定作者布局和 `physics_variant=0`，环境光与两盏方向光同时乘以 0.85、0.95、1.05、1.15，颜色比例不变。不得将 L1–L10 任务代码解释为权限 Level 1。五种机器人保留原控制器，物理 240 Hz、控制 20 Hz、成功稳定 1 s；长程为 6000 步 / 300 s，几何和动力学为 2400 步 / 120 s，墙钟均为 3600 s。动力学合同中的 5–20 s 截止仍独立生效，一秒稳定必须在任务截止前完成。

每 base seed、固定权限与观测组合为 510 组、2040 回合：发射器 800，其他 1240。四级分别运行共 8160 个计划回合。工程 base seed 0、1、2 共 6120 个正式协议计划项；额外物性不混入正式统计。

统一入口使用独立进程监督器实施墙钟硬截止，包含仿真初始化。正常超时计为有效失败，不因超时增加机会；经审计确认的非 agent 故障才按共享规则剔除并补跑。直接使用原生 Gym 开发入口不具备受控测评边界。早期 v1 调用仅限原 350 项；历史证据保留原版本。
