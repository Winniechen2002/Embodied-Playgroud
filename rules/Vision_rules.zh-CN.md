# Level 1：视觉、几何与代理仿真强化学习

遵循[共享规则](rules.zh-CN.md)，包括所声明实验的资源预算与冷启动要求，以及所选环境的任务说明。Level 1 明确在允许代码的 L0 基线上增加预置领域及视觉工具；该基线见 [rules_model_only.md](rules_model_only.zh-CN.md)。Level 1 允许由视觉得到的几何、IK、重定向、规划、反馈控制，以及由观测重建的代理仿真中的强化学习/优化。方法档位：`vision_geometry_proxy_rl`。

各次尝试遵循共享规则中的冷启动隔离要求。
遵循[共享尝试隔离规则](rules.zh-CN.md#section-6)。

<a id="section-2"></a>
## 允许的输入与信任边界

智能体、辅助智能体和外部模型可使用已声明的相机 RGB、内参/外参、机器人模型及关节限位、关节位置/速度、符号任务/目标和物体尺寸顺序、当前回合动作历史、当前尝试中的合法轨迹，以及由这些输入得到的估计。

宿主为当前回合公开的发射器弹簧刚度，是 Level 0–3 均可获得的明确任务参数。
可以直接用于推理、控制，以及 Level 1/2 代理仿真的初始化，无需从 RGB 估计。
这是隐藏动力学限制中的一个明确公开项，不提供其他仿真参数或场景几何；
详见[四次测试协议](../docs/evaluation/marble.zh-CN.md)。

原生深度、掩码、分割、ID、点云、光流、法向量、包围框和接触均为特权信息，除非明确声明为渲染传感器观测。两种汉诺塔 Vision 接口都只公开一个 `policy` 组：`rgb`、`joint_pos`、`joint_vel`、`actions`。环境 ID 见 [Franka](../docs/evaluation/hanoi_panda.zh-CN.md) 和[Floating Sharpa](../docs/evaluation/hanoi_floating.zh-CN.md)。仅运行环境不等于使用独立评分评测器。

不得读取仿真器物体/夹爪世界位姿、未公开的动力学、接触、允许的本体感知之外的物理张量、USD/场景图、物体句柄、重置种子/原点、任务物体资产/生成器或私有评测器状态。禁止用公开或记忆中的任务尺寸、名义坐标、堆叠高度和特定种子先验替代感知。当前尝试内的轨迹复用不允许引入其他回合数据或隐藏场景几何。将禁止的信息经文件、图像、提示词、缓存或辅助进程传递，并不会使其变得合法。

评测器私下监控每个物理子步并决定成功与否。执行期间，它可以停止失败运行，但不得公开特权分类、原因或快照。回合结束后公开信息，并不意味着可在之后的 Level 1/2 尝试中复用特权信息。

<a id="section-3"></a>
## 感知与控制

只使用[共享白名单](rules.zh-CN.md#section-8)中的 Level 1 工具。Depth Pro、Depth Anything 3、采用 SAM3D 的 Stream3D 和 SAM 3D Objects 是获准的感知/重建模型。禁止 TRELLIS.2 实现、TRELLIS.2 检查点和 TRELLIS 运行脚本，也禁止未列出的学习型视觉模型与远程感知服务。

用于抓取、避障和放置的场景几何须来自声明的合法观测。Level 0 的基础计算与自行实现算法权限继续适用；明确授权的外部感知模型是可选新增工具，不是自行实现算法的前提。机器人运动学和传感器标定可变换观测推导的估计；隐藏仿真状态和针对种子拟合的先验仍不可用。

每次操作都应依据当前观测，生成、复用或调整轨迹，并执行必要验证。兼容的复用片段不需要从零重新重建目标。通过动作接口执行，并在每次搬运后观察，确认释放/就位后再开始下一次搬运。跟踪不确定性需要时在执行中观察；否则复用缓存估计。智能体的所有视觉检查都遵守共享图像预算。

<a id="section-4"></a>
## 重建的代理仿真与学习

Level 1/2 可根据当前评测回合收集的观测新建代理仿真。代理仿真可向 RSL-RL/Optuna 公开完整代理物体状态、接触、动力学和自定义代理奖励，用于训练、奖励/轨迹优化和模型选择。策略可在获准运行期间从零开始；不允许导入额外的预训练或此前微调过的动作策略检查点/控制器。该限制不禁止被测模型自身事先声明并冻结的权重。

每个代理资产/参数都必须能追溯到合法帧、标定、机器人模型、符号任务、当前回合明确公开的任务参数或白名单模型输出。不得从原始仿真器资产、尺寸、隐藏状态、接触、原始奖励、评测器诊断、重置种子或此前回合场景数据初始化或纠正它。可将复用轨迹作为当前代理仿真中的候选动作测试；轨迹不能提供代理场景几何或特权训练标签。原始仿真器的成功/失败不能作为可用的优化目标。

部署时使用观测适配器，移除所有仅在代理仿真中存在的状态。使用同一回合后续合法 RGB、本体感知及智能体自己的动作历史更新代理仿真。这不增加原始仿真器回合或重置。资产和日志标为 `derived/proxy`；来源、奖励、训练/试验配置、种子、结果、检查点及部署观测结构须与评测器日志分开记录。

<a id="section-5"></a>
## 汉诺塔硬规则

Franka 与Floating Sharpa 均遵循规范[汉诺塔任务](../docs/evaluation/hanoi_panda.zh-CN.md)。它规定合法搬运、共享预算、就位/穿透容差、逐子步失败处理和精确目标匹配。机器人专用任务文件定义接口和评测器可用情况。这些评分标准不授予 Level 1/2 智能体特权测量；仅凭视觉估计不能判定成功。

<a id="section-6"></a>
## 证据与结果

保存共享审计证据、模型几何无损输出、派生掩码/深度/点云、位姿/抓取估计及其不确定性，以及代理仿真来源。保留汉诺塔输出字段：`status`、`success_tolerance_met`、`vision_only_compliance`、`hanoi_rule_result`（status/reason/violating_ring/state_snapshot）以及 `visual_evidence`（video/observation_log/trajectory_log）。

物理失败仍可能符合视觉权限要求，但任务失败；记录 `HanoiRuleViolation` 及发生阶段。禁止的特权访问会设置 `vision_only_compliance: false` 和 `PrivilegedObservationViolation`。保留首次违规，私有终局状态只在执行结束后公开。总体成功要求方法合规与任务成功同时成立。
